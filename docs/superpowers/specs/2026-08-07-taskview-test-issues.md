## 一、本次测试新发现的问题（未修复）

### 问题 1：实体 type 不可编辑
- **来源用例：** B-02
- **现象：** 编辑表单中 `type` 是只读标签（`type: task`），没有输入框，用户**无法通过表单修改实体类型**（如把 task 改成 click）。
- **影响：** 中。改变实体类型需手动编辑配置文件。
- **复现：** 选中任意实体 → 表单无 type 输入框。
- **建议方向（未实施）：** 增加 type 下拉选择（基于 `SectionType` 枚举）。

### 问题 2：settings 容器 fields 引用不可编辑
- **来源用例：** B-08
- **现象：** `settings` 类型实体在表单中只渲染通用字段，其 `fields` 引用（子 setting 列表）不显示、不可编辑；`setting` 类型实体的 `setting_type/options` 等专有字段也未在表单中出现。
- **影响：** 中。无法通过可视化方式配置 settings/setting 结构。
- **复现：** test.txt 新增 `zz-settings`/`zz-setting` → 选中 → 表单无专有字段。
- **建议方向（未实施）：** 表单为 settings 类型补 `fields` 字段（引用补全），为 setting 类型补 `setting_type/options/default`。

### 问题 3：选中未保存新节点触发 /api/entity 404（console 噪音）
- **来源用例：** E-03
- **现象：** 选中乐观更新新增的（未保存）节点时，前端 fetch `/api/entity/{key}` 返回 404（浏览器 console 记录错误）；功能已兜底（构造临时 detail，表单可用），但 console 有 404 噪音。
- **影响：** 低。功能正常，仅日志噪音。
- **复现：** 新增实体 → 选中该节点 → console 出现 404。
- **建议方向（未实施）：** 对未保存（dirty/新建）节点跳过后端 fetch，直接用节点信息构造表单。

### 问题 4：graph 视图不显示跨文件引用边
- **来源用例：** A-02
- **现象：** graph 视图按当前文件渲染，`test` 的 action 引用 `get-combat-power/context-check`（MainMenu 实体）**不显示引用边**；flow 视图可见（J-01 验证）。
- **影响：** 低。设计局限（graph 视图范围=单文件），非缺陷。
- **建议方向（未实施）：** 若需在 graph 视图展示跨文件引用，需改 `build_graph` 加载全部实体池。

### 问题 5：新增实体默认 target 校验拦截的 UX 引导不足
- **来源用例：** E-02
- **现象：** 新增实体默认 `target=buttons\xxx.png`（占位符），直接保存被"图片资源不存在"校验拦截。错误横幅会提示，但用户首次使用时可能困惑。
- **影响：** 低。严格校验是设计预期，但默认值会误导。
- **建议方向（未实施）：** 新增时默认 target 留空（不触发图片校验）或提示先填 target。

### 问题 6：flow 视图选中跨文件节点 → 字段值丢失
- **来源用例：** FV-02（flow 专项测试）
- **现象：** flow 视图流程树含跨文件节点（如 `get-combat-power#1` 在 MainMenu）。选中时前端 fetch `/api/entity/get-combat-power?file=test.txt` 返回 404（实体不在 currentFile），兜底 detail 只有 key/type，**实体真实字段（func/target/args 等）全部为空**，用户看不到也无法正确编辑。
- **影响：** 中。flow 视图对非当前文件实体的编辑不可用。
- **复现：** 切 flow → 选中 `get-combat-power#1` → 表单 func/args 为空。
- **建议方向（未实施）：** tap handler 需用节点实际所在文件请求 detail（flow 数据可携带实体来源文件），或 `/api/entity` 支持全局按 key 查找。

### 问题 7：flow 视图下节点脏标记 / 删除标红失效
- **来源用例：** FV-03 / FV-06（flow 专项测试）
- **现象：** flow 视图节点 id 带 `#N` 后缀（`test#1`），但乐观更新的 `trackDirty`/删除分支用裸 key（`cy.getElementById('test')`）查找，找不到节点 → **改字段无黄色脏标记、删除无红色标记**（草稿栏与 op 记录正常）。
- **影响：** 低-中。操作状态反馈缺失，用户不知道哪些节点被改/待删。
- **复现：** 切 flow → 选中 `test#1` → 改字段 → 节点无脏标记；删除 → 无标红。
- **建议方向（未实施）：** `trackDirty`/删除查找用 `cy.$('[id^="key#"]')` 匹配 flow 节点。
